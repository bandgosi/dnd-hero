# Перенос «D&D Героя» на другой iPhone (v48)

1. На старом iPhone откройте приложение, в котором находятся ваши герои, и нажмите **☰ Герои → Экспорт**. Будет подготовлен один JSON со всеми героями, фотографиями, характеристиками, заклинаниями, предметами, заметками и историей бросков. Последние изменения открытого героя включаются сразу, без ожидания автосохранения.
2. Сохраните `dnd-герои-ДАТА.json` в **«Файлы» → iCloud Drive** или передайте файл через AirDrop. Убедитесь, что файл действительно появился и имеет ненулевой размер. Сообщение приложения означает подготовку файла; завершение сохранения выполняет iOS.
3. На новом телефоне откройте приложение один раз онлайн. Если используете иконку на домашнем экране, импортируйте именно в это установленное приложение. Safari и установленное веб-приложение могут использовать разные хранилища.
4. Откройте **☰ Герои → Импорт** и выберите файл. Если файл находится в iCloud, сначала дождитесь его загрузки на устройство. После проверки файла и успешной записи приложение покажет количество добавленных героев.
5. В меню героев проверьте количество и имена, откройте каждого героя, посмотрите фотографию, характеристики, заклинания, сумку и журнал.
6. Закройте и снова откройте приложение на новом телефоне. Проверьте героев ещё раз. После первого онлайн-запуска можно включить авиарежим и проверить офлайн-открытие. Сохраните исходный JSON и данные на старом iPhone до окончания проверки.

**QR/«Поделиться» передаёт только одного героя без фотографии и истории бросков. Для полного переноса нужен JSON.**

## Повторный импорт и конфликты

- Импорт добавляет героев, сохраняя уже имеющихся.
- Повторный импорт той же копии не создаёт дубликаты, включая случай, когда импортированного героя уже изменили на новом телефоне. Это не двусторонняя синхронизация и не команда восстановления поверх текущего героя.
- Если идентификатор совпал, а данные отличаются, существующий герой остаётся на месте; импортируемая версия получает отдельный идентификатор. Повторная загрузка этой же версии больше не добавляет копию.
- Файлы старого полного экспорта `{active,list}` и одиночные `{state,fields}` / `{fields}` поддерживаются. Для старых файлов доступна проверка структуры; контрольной суммы в них ещё нет.

## Ошибки

- **Повреждённый JSON, неверная структура, отсутствующий активный герой, повторяющиеся идентификаторы, неподдерживаемая версия или неверная SHA-256:** весь импорт отменяется до записи. Имеющиеся данные остаются на месте.
- **Файл пуст, больше 25 МБ или недоступен из iCloud:** файл не импортируется; выберите полный, загруженный файл.
- **Хранилище заполнено / запись запрещена:** сообщение об успехе не появляется, прежняя запись и открытый герой сохраняются. Не закрывайте приложение с несохранёнными изменениями. Экспорт JSON включает текущую форму даже при отказе записи в `localStorage`. После сохранения резервного файла уменьшите объём фотографий/данных в приложении и повторите импорт. Свободное место на диске само по себе не увеличивает квоту `localStorage`.
- **Хранилище не читается:** оно не заменяется персонажем по умолчанию. При недоступном чтении полный экспорт тоже невозможен; не очищайте данные сайта, пока не найдена резервная копия.

Проверка SHA-256 обнаруживает изменение содержимого файла; это не электронная подпись и не подтверждение автора файла. Расчёт выполняется локально, в том числе офлайн. Требуется HTTPS (либо localhost при разработке), как для установки PWA.

## Раскрытый экран и прокрутка

От 720 CSS-пикселей полезной ширины, после вычета безопасных полей iOS и границ, приложение занимает всю ширину экрана и показывает две панели:

| Раздел | Слева | Справа |
|---|---|---|
| Герой → Основное | Портрет, обзор и параметры | Опыт, предыстория и особенности |
| Герой → Бой | Здоровье и состояния | Атаки, ячейки и ресурсы |
| Герой → Характеристики | Значения и пассивные показатели | Спасброски и навыки |
| Магия | Ячейки, поиск и список | Выбранное заклинание |
| Сумка | Монеты, поиск и предметы | Выбранный предмет |
| Кубики | Управление бросками | История |
| Журнал | Кампания и локации | NPC и остальные заметки |

У каждой панели своя прокрутка. На узком экране сохраняется мобильный режим; поля и выбранные данные не пересоздаются при повороте или раскрытии. Раскладка зависит от полезной ширины окна, а не от названия модели телефона.

## Автоматические проверки

Установите Playwright для разработки и Chromium:

```sh
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install --with-deps chromium
node tests/transfer.cjs
node tests/dual-pane.cjs
node tests/responsive.cjs
node tests/redesign.cjs
node tests/art.cjs
node tests/visual.cjs
node tests/ios-layout.cjs
```

Приложение не загружает Playwright или другие новые зависимости. Каждый тест запускает временный локальный HTTP-сервер и закрывает его после выполнения. `CHROMIUM_EXECUTABLE` позволяет использовать установленный браузер. `REVIEW_SCREENSHOTS=/absolute/path` включает снимки для `dual-pane.cjs`.

Все семь наборов автоматически запускаются в GitHub Actions на pull request и при изменении `main`. `transfer.cjs` использует реальные загрузки файлов и два изолированных браузерных контекста, сравнивает все данные трёх героев после офлайн-перезагрузки и повторного экспорта; проверяет старые форматы, повторный импорт, коллизии, повреждения, реальную квоту браузера, отказ доступа и спасательный экспорт. `dual-pane.cjs` проверяет реальную независимую прокрутку колесом, семь широких размеров, узкие режимы и сохранение DOM при изменении ширины.

Эти проверки выполняются в Chromium. Финальная проверка файлового диалога iOS, AirDrop/iCloud, жестовой прокрутки и установленных PWA в Safari на физическом iPhone остаётся ручной.
