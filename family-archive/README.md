# История нашего рода — семейный архив

Веб-приложение для ведения семейного архива: интерактивное древо, импорт наброска семьи из Excel, карточки людей с датами, биографиями и фотографиями, очередь уточнения связей, история изменений, резервные копии.

Главный принцип: **исходные сведения, предположения приложения и подтверждённые вами факты хранятся раздельно**. Фамилия, отчество, соседство ячеек, рамки и объединения в Excel никогда не превращаются в связи сами по себе — только в вопросы с объяснением. Даты, пол, фамилии и жизненный статус не заполняются догадками.

## Быстрый запуск

Нужен [Node.js](https://nodejs.org/) **22.13 или новее** (подойдёт актуальная LTS-версия).

```bash
cd family-archive
npm install
npm start
```

Откройте в браузере **http://localhost:3000**. При первом запуске интерфейс собирается автоматически (несколько секунд).

Дальше:

1. Раздел **«Импорт из Excel»** → «Выбрать файл» (имя файла может быть любым).
2. Проверьте предпросмотр: схему листа, список записей, черновой разбор ФИО и возможные связи. По умолчанию люди импортируются **без** подтверждённых связей.
3. Нажмите «Импортировать». Все записи появятся в архиве, предположения — в разделе **«Уточнить связи»**.

Импорт можно выполнить и из командной строки: `npm run import -- "путь/к/файлу.xlsx"` (с `--dry-run` — только проверка).

Остановить сервер — `Ctrl+C`. Данные сохраняются на диске и доступны после перезапуска.

## Где хранятся данные

Всё лежит в папке `family-archive/data/` (её можно изменить переменной `DATA_DIR`):

| Что | Где |
|---|---|
| База данных SQLite | `data/family.db` (+ служебные `family.db-wal`, `family.db-shm`) |
| Фотографии (файлы) | `data/photos/<id>/original.*`, `display.*`, `thumb.*` |
| Исходные файлы Excel | `data/imports/<контрольная сумма>.xlsx` |
| Резервные копии | `data/backups/*.zip` |

Пути также показаны в разделе «Архив». Папка `data/` исключена из git — семейные данные не попадают в репозиторий. Браузерное хранилище используется только для удобств интерфейса (вид списка, свёрнутые ветви), не для данных.

## Как пользоваться

### Подтвердить связь
1. Откройте **«Уточнить связи»**. Каждый вопрос показывает исходные записи с координатами ячеек и предположения с объяснением («Почему так предположено»).
2. Для известной связи нажмите **«Подтвердить…»**, при желании укажите тип (например, «Биологический» или «Брак»).
3. Если связь другая — **«Указать связь»**: выберите людей и вид связи (родитель, ребёнок, партнёр или «это один человек»). Неверное — **«Отклонить»**, не знаете — **«Позже»**.
4. Ошибочно подтвердили? В вопросе нажмите **«Исправить»** (связь удалится, предположение вернётся в очередь) или откройте связь в карточке человека и удалите её.

Подтверждение одного родителя не назначает второго и не создаёт брак. Предположения не участвуют в древе и в родственных подписях.

### Добавить родственника
- Кнопка **«Добавить человека»** вверху: имя, при желании пол, статус, дата рождения и связь с кем-то из архива. Если похожая запись уже есть, приложение предложит выбрать её вместо создания дубля.
- Или в карточке человека: вкладка **«Связи»** → «+ Родитель», «+ Ребёнок», «+ Партнёр» → «Выбрать из архива» или «Новый человек».

### Изменить сведения и фотографию
- В карточке нажмите **«Редактировать»**: ФИО, фамилия при рождении, другие имена, даты с точностью (полная дата, месяц и год, только год, приблизительно, диапазон, неизвестно), статус, пол, места, биография, заметки. Исходная строка Excel при этом не меняется.
- Фото: в карточке **«Загрузить фото»** → выберите JPEG/PNG/WebP → выберите кадр → «Сохранить фото». Затем доступны «Заменить», «Кадрировать», «Ещё фото», «Удалить». При загрузке фото уменьшается (по умолчанию до 2048 px) и сжимается, данные о месте съёмки удаляются; кадр и миниатюра хранятся отдельно.

### Древо
- «Семейное древо» — только подтверждённые связи; «Исходная схема Excel» — расположение записей как в файле, с границами ячеек.
- «Показать предположения» — пунктирные линии с маркером «?»; нажатие на маркер открывает объяснение и действия.
- Масштаб колёсиком/жестом и кнопками, «Показать всё», «К выбранному»; миникарта при большом графе.
- Меню карточки «⋮» → «Сделать центром древа» — появляются родственные подписи и выбор «Ближайшие / Предки / Потомки / Вся семья». Кнопки на карточках сворачивают ветви.

## Резервное копирование и восстановление

- **«Архив» → «Создать резервную копию»** — один `.zip`: люди, связи, предположения, вопросы, источники, история, исходные Excel и все фотографии. Формат копии имеет номер версии (сейчас 1).
- Автоматическая копия делается раз в сутки при работающем сервере и только если были изменения (хранятся последние 3, на сервере — 2), а также перед откатом импорта, восстановлением и обновлением. Если копия не получилась (например, мало места), раздел «Архив» об этом скажет.
- Копия читается по каталогу ZIP с проверкой контрольных сумм каждого файла: повреждённая копия не восстановится частично. Данные копии разбираются и записываются отдельным процессом с собственным ограничением памяти, поэтому даже испорченный файл не нарушит работу сервера. Восстановить через приложение можно копию с файлом данных до 32 МБ (это сотни тысяч записей); если данные вырастут больше, приложение предупредит при создании копии.
- История изменений хранит последние 50 000 записей.
- Скачайте копию («Скачать») и храните её отдельно от компьютера.
- Восстановление: «Восстановить из файла…» (или «Восстановить…» у сохранённой копии) → проверьте сравнение «сейчас / в копии» → введите слово «восстановить». Текущие данные заменяются, прежнее состояние автоматически сохраняется в отдельную копию.
- «Люди (CSV)» и «Связи (CSV)» — таблицы для Excel (UTF-8, разделитель «;»), с точностью дат и исходными строками.

## Повторный импорт и откат

- Тот же файл (по контрольной сумме) повторно не импортируется — дублей не будет.
- Изменённая версия файла открывает **сверку различий**: без изменений / изменён текст / новая / перемещена / отсутствует. Если вы правили человека вручную, по умолчанию правки сохраняются. Совпадение ФИО не считается поводом для слияния.
- **Откат импорта** (история в разделе «Импорт из Excel») сначала показывает последствия: кто будет удалён, а кто сохранится, потому что у него есть ваши правки, фото или подтверждённые позже связи.

## Установка на сервер

Подходит небольшой виртуальный сервер: Ubuntu 22.04/24.04 или Debian 12, 1 процессор, 1 ГБ памяти, от 500 МБ свободного места плюс место под фотографии. Установщик всё делает сам одной командой.

### Что понадобится
- **Доменное имя** для HTTPS, например `archive.example.ru` (подойдёт и бесплатный поддомен вроде DuckDNS). В настройках домена создайте запись **A** с IP-адресом сервера. Без домена архив можно открыть только через SSH-туннель (режим `--local-only`).
- Доступ к серверу по SSH с правами `sudo`.

### Установка
```bash
sudo apt install -y git     # если git ещё нет
# скачать только папку архива (~2 МБ, а не весь репозиторий):
git clone --depth 1 --filter=blob:none --sparse -b claude/wonderful-clarke-xp7nfo https://github.com/bandgosi/dnd-hero.git family-archive-src
cd family-archive-src && git sparse-checkout set family-archive && cd family-archive
sudo bash deploy/install.sh --domain archive.example.ru
```
Установщик спросит пароль для входа (или создаст случайный с `--generate-password`). Затем откройте `https://archive.example.ru`, войдите и импортируйте Excel. Если порт 3000 на сервере уже занят другой программой, установщик скажет об этом — укажите другой: `--port 3010`. Домен можно добавить или исправить позже тем же запуском с новым `--domain`, а `--local-only` отключает доступ из интернета (данные и пароль сохраняются). Если ветку `claude/wonderful-clarke-xp7nfo` уже влили в `main`, параметр `-b …` можно не указывать.

Перенести то, что уже сделано на своём компьютере: там «Архив» → «Создать резервную копию» → «Скачать», на сервере — «Архив» → «Восстановить из файла…».

### Что и где установлено
| Что | Где | Размер |
|---|---|---|
| Node.js 22 (с nodejs.org, контрольная сумма проверяется) | `/opt/node` | ~140 МБ |
| Приложение и готовый интерфейс | `/opt/family-archive` | ~11 МБ |
| Caddy — HTTPS с бесплатным сертификатом Let's Encrypt | пакет `caddy` | ~40 МБ |
| Данные: база, фото, копии (доступ только у службы) | `/var/lib/family-archive` | растёт с фото |
| Настройки и хэш пароля (доступ только у root) | `/etc/family-archive/env` | — |

Интерфейс в репозитории хранится уже собранным, поэтому на сервере ничего не компилируется: это экономит место и память.

### Фотографии и место на диске
- При добавлении фото браузер **уменьшает его до 2048 пикселей** по длинной стороне и сжимает в JPEG: снимок с телефона 3–5 МБ превращается примерно в 0,3–0,8 МБ. Ещё хранятся кадр для карточки (800 px) и миниатюра.
- Метаданные снимка — **координаты места съёмки (GPS)**, модель телефона, комментарии — удаляются: и в браузере, и повторно на сервере. Сервер принимает только уменьшенные фото.
- Размер и качество меняются в `/etc/family-archive/env` (`PHOTO_MAX_SIDE`, `PHOTO_QUALITY`).
- Резервные копии: автоматическая копия создаётся раз в сутки и **только если были изменения**. Хранятся 2 последние, а также 2 копии «перед обновлением/откатом/восстановлением»; если места мало, перед новой автоматической копией удаляется самая старая. Копии, созданные вручную, удаляйте в разделе «Архив», предварительно скачав. Если автоматическая копия не получилась, раздел «Архив» об этом скажет.
- Приложение всегда оставляет на диске не меньше 300 МБ свободными: при нехватке места сохранение изменений, фото или копии отклоняется с понятным сообщением, а не обрывается на середине (удалять можно всегда — это освобождает место). Раздел «Архив» показывает, сколько места занимают фото, копии и база.
- Ориентир для ~4 ГБ свободного места: каждая копия содержит все фото, поэтому вместе с копиями фото занимают примерно в 5 раз больше своего размера. Фото с кадром и миниатюрой — около 1 МБ, то есть помещается **примерно 700–900 фотографий**. Чтобы хранить больше, скачивайте копии на свой компьютер и удаляйте старые, либо увеличьте диск виртуальной машины.

### Управление на сервере
```bash
sudo family-archive status     # работает ли служба, сколько места занято
sudo family-archive logs       # журнал
sudo family-archive backup     # резервная копия прямо сейчас
sudo family-archive password   # сменить пароль (все устройства выйдут)
sudo family-archive update     # обновить: git pull, копия, установка, откат при ошибке
```
Обновления безопасности Ubuntu и Caddy ставятся автоматически (unattended-upgrades). Приложение обновляйте командой `update` примерно раз в месяц: она же обновит Node.js до свежей версии 22.x и Caddy. Если новая версия не запустится, вернётся прежняя (вместе с прежним Node.js и настройками службы), а путь к резервной копии «перед обновлением» будет показан. Брандмауэр настраивается только при первой установке — обновление не меняет его правил.

### Безопасность
- Приложение слушает только `127.0.0.1`, наружу его открывает Caddy по HTTPS. Порт держит сам systemd (`family-archive.socket`), поэтому даже во время перезапуска его не может занять другая программа. Брандмауэр `ufw` пропускает только SSH (с ограничением частоты подключений; установщик находит все порты SSH и спрашивает подтверждение), 80 и 443; порт приложения снаружи закрыт.
- Служба работает от отдельного системного пользователя без входа в систему, в «песочнице» systemd: файловая система только для чтения (кроме папки данных), запрет повышения привилегий, модулей ядра, сырых сокетов и опасных системных вызовов, ограничение памяти.
- Вход только по паролю: на сервере хранится не пароль, а его хэш scrypt. Попытки подбора ограничены: 10 за 15 минут с одного адреса (для IPv6 — с одной сети /64) и 50 со всех; одновременно проверяется не больше нескольких паролей. Если кто-то устроит подбор, устройства, с которых семья уже входила, всё равно смогут войти. Сеанс — защищённая cookie (HttpOnly, Secure, SameSite=Strict). Смена пароля завершает все сеансы; есть кнопка «Завершить все сеансы» на случай потери телефона.
- Изменяющие запросы с чужих сайтов отклоняются (проверка Origin и служебного заголовка), заголовок Host проверяется. Действуют строгая политика безопасности содержимого (CSP), HSTS и запрет встраивания в чужие страницы.
- Загружаемые файлы проверяются по содержимому и размеру. Изображения на сервере не декодируются: нет уязвимого кода обработки картинок. Excel и резервные копии читаются по каталогу ZIP с проверкой контрольных сумм и распаковываются с ограничением объёма (защита от «zip-бомб»), у Excel ограничены число ячеек, элементов и атрибутов XML и общий объём текста; большой лист показывается в схеме сжато, а не отклоняется. Имена файлов из копий проверяются по белому списку, поэтому выйти за пределы папки данных нельзя; из копии распаковываются только файлы, на которые ссылаются данные. Значения, похожие на формулы, в CSV экранируются, ссылки в источниках — только http(s).
- Память расходуется экономно: резервные копии пишутся и читаются потоком (копия на сотни мегабайт добавляет к памяти службы лишь десятки), тяжёлые загрузки обрабатываются по очереди.
- Если включён доступ из сети, приложение не запустится без пароля и без явного доменного имени (`ALLOWED_HOSTS`).

Сам сервер тоже стоит защитить: вход по SSH-ключу вместо пароля, запрет входа под root, надёжный пароль от панели хостинга. Если доступ по SSH потерян, остаётся консоль в панели Proxmox.

### Удаление
```bash
sudo systemctl disable --now family-archive family-archive.socket
sudo rm -rf /opt/family-archive /etc/family-archive /etc/systemd/system/family-archive.service /etc/systemd/system/family-archive.socket /etc/systemd/system/family-archive.service.d /usr/local/sbin/family-archive /etc/caddy/conf.d/family-archive.caddy /etc/apt/apt.conf.d/51family-archive-caddy
sudo systemctl daemon-reload && sudo systemctl reload caddy
# данные (сначала скачайте резервную копию!): sudo rm -rf /var/lib/family-archive
```

## Доступ из сети и приватность

По умолчанию (без установщика) сервер слушает только `127.0.0.1` — архив доступен лишь с этого компьютера, данные никуда не отправляются, внешних сервисов и шрифтов из интернета нет. Для доступа семьи используйте установку на сервер (выше): там пароль, HTTPS и защита настраиваются автоматически. Ручная настройка: скопируйте `.env.example` в `.env`, задайте `APP_PASSWORD_HASH` (`npm run hash-password`), `ALLOWED_HOSTS`, `TRUST_PROXY=loopback` и `COOKIE_SECURE=1`, поставьте перед приложением HTTPS-прокси. Без пароля приложение отклоняет запросы, пришедшие через прокси или туннель.

## Технические решения

- **Сервер:** Node.js + Express 5. **База:** встроенный в Node.js SQLite (`node:sqlite`) — без компиляции нативных модулей. Схема и миграции — `server/migrations/`.
- **Excel:** собственный разбор OOXML (`fflate` + `fast-xml-parser`): видимость листов, точные строки с пробелами, объединения, границы ячеек (в том числе пустых), рамки, ширины столбцов, проверка формул, комментариев, таблиц и рисунков.
- **Интерфейс:** React + React Flow (холст, масштаб, миникарта) + dagre (раскладка поколений), иконки Lucide, шрифты Literata и Manrope поставляются локально.
- **Фотографии:** уменьшение, сжатие и кадрирование в браузере; сервер проверяет формат по содержимому и размеры, удаляет метаданные (EXIF/GPS) без декодирования изображения и хранит файлы на диске.
- **Готовая сборка интерфейса** лежит в `client/dist` вместе с отпечатком исходников (`build-info.json`). После изменений в `client/` или `shared/` выполните `npm run build` и закоммитьте `client/dist` — иначе тест `tests/unit/dist.test.js` не пройдёт.

Режим разработки: `npm run dev` (интерфейс на http://localhost:5173 с горячей перезагрузкой).

## Проверки

```bash
npm test                                   # модульные и API-тесты на вымышленных данных
npm run check:file -- "файл.xlsx" --expect=30   # проверки готовности на вашем файле (во временной папке)
npm install --no-save playwright && npm run build && npm run test:e2e   # проверка интерфейса в браузере
```

Тестовые данные вымышлены и создаются во временных папках; рабочая база не затрагивается. `check:file` и `test:e2e` (с переменной `FAMILY_XLSX`) можно запускать на собственном файле — данные останутся только во временной папке и будут удалены.

## Структура

```
server/        API, база, миграции, импорт Excel, фото, копии
```
